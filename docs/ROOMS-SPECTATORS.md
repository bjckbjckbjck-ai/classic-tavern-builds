# 房间列表、公开观战与彻底退出

发布状态：已在现有房间自然结束后部署；公网好友房与积分赛观战、退出验证通过。

客户端 0.61.0-service7；服务 0.3.0-preview，协议保持 service-2，旧客户端仍可正常对局。

## 使用方式

登录云端后，从好友房间或在线匹配大厅进入“服务器房间列表 · 加入 / 观战”。列表每 3 秒刷新，也支持手动刷新。

- 房间标明“积分赛”或“好友房”、桌号、房间码、阶段和真人数量，自己的房间标记为当前房间。
- 未开局且有真人空位的好友房可以加入；当前房间提供重连。积分赛通过匹配进入，不能从列表插入正在进行的比赛。
- 两种房间均能观战，包括等待开局和选择英雄。观众不占 8 人对局席位，也不计分；每桌最多 8 个同时在线的观战连接。尚未对额外观众做满容量压测。
- 观战展示公开阵容和战斗，可以点击左侧玩家切换；手牌、商店、发现选项、英雄候选、饰品候选和战斗中的私有手牌记录不会发给观众。观战动作只允许切换目标和跳过自己的回放。

离开时有两种选择：

- 暂时离开：保留房间绑定，离线期间 AI 托管，能重连原席位。
- 彻底退出：确认后解除房间绑定，可以立即创建/加入其他房间；不再允许回原局参赛，但可以观战。开局后的原席位由 AI 继续，未开局则释放座位并在必要时移交房主。最后一名真人彻底退出后结束房间并释放桌位。
- 好友房不扣积分。积分赛在未淘汰时退出按第 8 名计分；已淘汰保留实际名次。沿用原本混合 AI 半积分、单人 AI 不计分规则。结算幂等，旧局以后结束不会再次扣分。

## 实现与验证

- 新增只读 `/api/rooms` 和签名观战票据 `/api/spectate`；`/api/leave` 接收明确的 permanent 与目标 room。目标房间校验防止延迟/重复退出请求误伤新房间。
- SQLite 增加 departures 表，旧库通过 CREATE TABLE IF NOT EXISTS 迁移。比赛成员历史和当前房间绑定分离，保留退出者结算资料。
- 桌进程同步退出名单，撤销既有连接和未使用票据；观众与真人连接判定分离，不能阻止 AI 托管或取得管理权限。
- 后端及更新辅助器共 17 项 pytest 测试通过；Godot 观战只读/隐私/回放隔离测试和原英雄选择、独立结束战斗回归通过。
- 本地真实三客户端验证通过：房间发现、观战、隐藏私有区、拒绝操作、切换目标、彻底退出、立即创建新房、旧票据拒绝、最后真人退出释放桌位。
- Windows 原生 UI 检查包含四行房间列表、退局确认、实际阵容与战斗观战画面，截图在 validation/client6。尚未进行实体 Android 观战和新增观众的容量压测。

服务切换要求没有活动对局和排队玩家，先做加密数据库备份，保留旧 API/桌进程文件用于回滚。运行中的客户端 EXE 不直接覆盖；本版客户端使用 build/service6 独立产物目录。先上传固定版本文件，服务验证完成后再切换自动更新清单。

并发边界补测：API 加入与桌进程开局共用短暂 admission.lock，开局前重新读入完整成员名单，写入英雄选择状态后才释放锁；避免加入/开局同时发生导致账号绑定了不存在的席位。积分赛实测使用真实等待 61 秒、2 名真人全部同意后与 6 个 AI 同桌，旁观无席位，退局各结算 -35 分。客户端构建提交与桌进程提交分别记录，本次最后的并发保护只影响服务器。
