# 云服务器交接与部署约定

状态：已部署预览版；当前主机可通过`deploy/deploy.ps1`重复部署，已实际执行验证。首次新主机仍须准备Python venv、Nginx、Certbot并配置备份公钥/定时任务；具体已部署状态见DEPLOYED.md。

## 服务器到位时所需信息

- 公网IP、SSH端口、登录用户名、操作系统/架构、CPU/内存/磁盘和公网带宽及月流量额度。
- SSH私钥在本机的文件路径（优先）及是否具备sudo；不需要将私钥正文提交到仓库。
- 游戏域名、DNS托管方、A/AAAA记录现状；如果只需要DNS指向公网IP，可由用户自己配置，无需额外DNS token。
- 若确实要自动修改DNS，再使用仅限目标域名的DNS权限token；SSH凭据、DNS token、GitHub token用途不同，不能混用。
- 现有GitHub授权可用于service-platform分支，无需另发GitHub token。
- 本地备份电脑的系统、目录、在线时间、每日接收时间、可达方式；公网不可达时使用私网或定时拉取。解密密钥由用户本地及离线另存。

## 预检与交付

1. 只读检查主机、已有服务/端口、磁盘、网络、DNS，避免覆盖现有应用。
2. 在独立目录安装经本地验证的版本化产物与服务；初始化数据库与配置。
3. 配置域名和HTTPS/WSS，开启所需入站端口；数据库、管理器和游戏内部端口不直接对公网开放。
4. 实际注册登录、排队、进入两桌、断线重连、结算及进程回收。
5. 完成32连接/4桌压测，验证第5桌不超开；交付地址、客户端、状态/日志/备份/回滚命令及验证报告。
6. 双模式托管重连、在线积分及60秒AI询问通过；执行每日备份实际送达、离线补传和隔离数据库恢复演练。

目标已降为4桌/32席，收到实际机器配置后以压测确定负载余量，不将旧8桌规格当最低购买要求。安装包独立下载，备份传输限速避免挤占对局带宽。

凭据不进入源码、截图、部署报告或命令输出；部署日志对授权头和票据脱敏。尚未连接任何云服务器或更改任何DNS。
