# 云服务器交接与部署约定

状态：部署流程设计，尚无可运行的一键脚本。

## 服务器到位时所需信息

- 公网IP、SSH端口、登录用户名、操作系统/架构、CPU/内存/磁盘和公网带宽及月流量额度。
- SSH私钥在本机的文件路径（优先）及是否具备sudo；不需要将私钥正文提交到仓库。
- 游戏域名、DNS托管方、A/AAAA记录现状；如果只需要DNS指向公网IP，可由用户自己配置，无需额外DNS token。
- 若确实要自动修改DNS，再使用仅限目标域名的DNS权限token；SSH凭据、DNS token、GitHub token用途不同，不能混用。
- 若要创建远程服务源码仓，确定账号/组织与可见性；建议私有。本地已建仓，无须为开始开发先提供GitHub token。

## 预检与交付

1. 只读检查主机、已有服务/端口、磁盘、网络、DNS，避免覆盖现有应用。
2. 在独立目录安装经本地验证的版本化产物与服务；初始化数据库与配置。
3. 配置域名和HTTPS/WSS，开启所需入站端口；数据库、管理器和游戏内部端口不直接对公网开放。
4. 实际注册登录、排队、进入两桌、断线重连、结算及进程回收。
5. 完成64连接/8桌压测后确定并发限制；交付地址、客户端、状态/日志/备份/回滚命令及验证报告。

初始机器建议仍是8 vCPU/16GB/80GB SSD/10Mbps可升级、Ubuntu 24.04 x86_64；不是容量保证。按真实结算与带宽峰值调整。安装包继续使用独立发行下载，避免占用对局带宽。

凭据不进入源码、截图、部署报告或命令输出；部署日志对授权头和票据脱敏。尚未连接任何云服务器或更改任何DNS。
