# Issue #33：服务器游戏优化

来源：https://github.com/bjckbjckbjck-ai/classic-tavern-builds/issues/33 （读取于2026-09-26，无附加评论）。

## 行为变化

1. 战斗在服务器权威结算后，只初始化一次下一轮。每位玩家保留独立的私有回放快照，自然播放完或点击跳过后立即进入自己的酒馆，可以购买、出牌等；别人的回放不被切走。退出消息带回合号，重复或过期消息不会重发金币或推进回合。未退出回放的席位不能抢先提交招募操作。下一轮战斗仍在全部玩家准备或统一招募截止后结算。超时回放自动结束，断线由AI托管。
2. 好友等待房只显示席位和设置。房主开始后进入复用单机样式的四选一英雄界面；全体真人确认立即开局，30秒未确认使用已提供的默认英雄。开始选英雄后禁止改房间设置、新玩家加入或释放已开局席位，仍能重连。
3. 队列页每2秒显示排队人数和AI同意人数。满8人直接开真人局；不足8人时，所有当前队列玩家均等待满60秒且明确同意后，一起进入同一桌，由最高难度AI填剩余席位。未同意、新加入或撤回同意都会继续等待；取消匹配会从人数及同意条件中移除。

协议：`allstars-0.61.0-service-2`；服务：`0.2.0-preview`；Android code：3。必须同时更新客户端，下载链接不变。原单机/LAN行为保留，账号数据库结构不变。

## 验证

- 10项隔离后端测试通过：新增全员同意共同分桌、迟到玩家/取消后的同意条件、满8人不需要AI同意；既有四桌上限、积分、恢复码等继续通过；新增Godot监听就绪后才签发票据的检查，防止刚分房立即连接收到502。
- Godot服务测试通过：选英雄前置限制、逐席位回酒馆购买、其他席位回放快照不变、过期/重复退出消息、终局排名；真人托管不获得永久AI经济加成回归通过。
- 本地真实API与两个WSS协议客户端通过：房主开始后选英雄、一人回酒馆购买时另一人仍在战斗、断线托管与原席位重连。
- 两真人实际等待61秒通过：仅一人同意仍保持2人在队列；第二人同意后同桌，两真人+6最高难度AI开局。
- Windows原生渲染通过：等待房无选英雄控件、四张英雄选择卡、确认入场、点击跳过后购买、自然播放及结算结束后自动回酒馆。截图见validation/0.2.0。
- 规则32项、离线UI7项、选英雄UI138项断言通过。旧选英雄测试漏计v0.59已经改为被动的克苏恩/死亡之翼，依据season-v59.json修正预期；没有改变其规则。
- Windows release导出并启动通过，Android debug导出且包名/版本号3核对通过；本轮未重新做实体手机、多运营商切网或32人长时间压力验收。
