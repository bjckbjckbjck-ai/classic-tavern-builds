## 原始要求与实现边界

用户要求依次去掉卡框和文字、形成悬浮感、以完整立绘为尾帧制作 16 张黑暗中红眼逐渐发光并显现环境的图片，最后合成连贯 GIF，并明确“可以不需要大幅形状位置变化”。

原始卡面分辨率较小，去框立绘由**内置 ImageGen** 根据原卡补全被遮挡区域和细节，不是逐像素裁剪，也不是未经修改的官方原画。提示词与输入均保留，可重新生成或改为项目正式美术。示范偏细致，后续新素材仍应遵守根目录 [AGENTS.md](../../AGENTS.md) 的手绘色块、夸张轮廓、简化背景要求；本次保留用户指定参考，不据此改变全项目美术规范。

悬浮感来自立绘中离地的前爪、地面阴影、蓝色灵体雾气，以及合成时**整幅画面**累计 6 px 的上移；本示范没有分离角色与背景，也没有实现骨骼动作、前后视差、落爪、怒吼动作或音效。

## 已实际执行的步骤

1. 查看原始卡面，明确狼的脸、双耳、银蓝鬃毛、前爪与金色护腕是需要保留的识别点。
2. 以原卡为编辑输入调用一次内置 ImageGen，去除卡框、星级、标题、文字和数值，补全无框矩形立绘；要求小范围红色眼睛、蓝白灵体光晕、前爪悬空。完整提示词见本目录，生成结果固定为 `goldrinn_artwork.png`。
3. **锁定这一张完整立绘作为尾帧基础**，缩放为 768 × 1024。后续帧都采样同一张图，不分别重画 16 次，避免脸部、爪位、饰物和构图漂移。
4. 用 Node.js + sharp 做确定性的动画合成：眼部红光独立渐亮，狼的主体比外围环境稍早显现，位移缓慢收敛；尾帧直接复制标准立绘，避免最后一帧发生光色跳变。
5. 导出 16 张 PNG、单次 GIF、循环审片 GIF、无损 WebP、4×4 分镜图及 JSON 参数；查看分镜和眼部位置，并完整解码 GIF 检查帧数与时长。

生图阶段可能受模型输出影响；本目录固定了实际生成的立绘，所以**合成阶段可以直接复现，不需要 API 密钥，也不会再调用生图服务**。

## 时间线与参数

总时长 **2550 ms**：前 15 帧共 **1550 ms**，第 16 帧停留 **1000 ms**。输出严格为 **16 帧、768 × 1024**，纵横比 3:4。

| 帧 | 时间段 | 可见内容 |
|---|---|---|
| 01–04 | 0–420 ms | 全黑起始，红眼从微弱逐渐亮起，轮廓基本不可见 |
| 05–08 | 420–820 ms | 红眼增强，狼的轮廓及环境逐步出现 |
| 09–15 | 820–1550 ms | 狼与森林连续提亮，上移幅度逐步收敛 |
| 16 | 1550–2550 ms | 完整立绘定格，与标准尾帧像素一致 |

令 `t = 帧索引 / 15`，索引从 0 开始。`smoothstep(a,b,t)` 先把 t 映射并限制到 0–1，再使用 `u²(3−2u)`。实际参数：

- 红眼强度：`smoothstep(0, 0.36, t)`。
- 主体曝光：`smoothstep(0.22, 1, t)^1.22`。
- 环境曝光：`smoothstep(0.32, 1, t)^1.15`。
- 垂直偏移：`6 × (1 − smoothstep(0, 1, t))` px；起始下偏 6 px，最终回到立绘原位。
- 眼位以原图 1086 × 1448 为基准：左眼 `(572,510)`、右眼 `(681,512)`，等比映射到输出。
- 眼部光源受现有暖色虹膜像素和局部高斯范围共同限制；亮度上升时额外红色光晕逐步减弱，最终恢复原立绘颜色。
- 每帧时长（ms）：`[120,100,100,100,100,100,100,100,100,100,100,100,100,100,130,1000]`。不能直接用统一 10 fps 替代这份时长表。

其他卡复用方法时，至少需要重设立绘、眼位、局部范围、主体曝光区域与特征颜色；狼爹的眼位和形状参数不是通用自动识别结果。

## 复现

安装 Node.js 22 或更高版本，进入本目录：

```sh
npm ci
npm run build
npm run verify
```

sharp 固定为 `0.35.4`，依赖版本锁在 `package-lock.json`。产物写入被 Git 忽略的 `generated/`，保留已提交的 `reference/` 作为原始审片基准；生成过程中的断言失败会使命令以非零状态退出。默认无需本机 Codex 依赖目录或任何绝对路径。

可选指定输出目录：

```sh
node build_goldrinn_animation.cjs /path/to/output
```

重新合成会写入同名产物，因此应选择独立输出目录。不同平台的字体渲染或编码库可能使分镜标签、压缩文件字节不同，验收以逐帧像素、时长和内容为准，不以 GIF 压缩字节完全相同作为跨平台承诺。

## 给项目的接入建议

下列是参考接入方向，尚未完成游戏端验证：

1. 先以这套“单张立绘＋眼部与环境光效＋微幅浮动”建立可审片样板。现有计划中的跃出、落爪、怒吼可作为后续增强；本示范证明的是显现流程，不证明那些大幅动作已经完成。
2. GIF 用作审片文件；游戏运行时可参考同一张纹理与曝光时间线，也可将 PNG 作为逐帧参考导入后制作对应资源。按 manifest 读取时长，保持主体纵横比，不直接把 16 张统一时长硬切。
3. 768 × 1024 × RGBA8 的单帧约 **3 MiB**；16 帧全部解码约 **48 MiB**，尚未包括 mipmap、缓存和其他资源，超过现有计划单次活跃演出 ≤12 MiB 的目标。不能把这些原尺寸帧全常驻后宣称达标；优先复用单图/遮罩与时间线，或降分辨率、按需加载并实测。
4. 示例为带森林背景的完整矩形画面，**不是透明角色层**。嵌入卡位或桌面时需明确遮罩/裁剪，若要角色与背景独立漂浮，需要先补分层素材。
5. 本样片的 2.55 秒含尾帧 1 秒停留。游戏内 1.2–1.6 秒目标应单独调整时间线并审片；可以缩短尾帧停留，不能将 2.55 秒直接写成已满足 1.6 秒要求。
6. 沿用现有计划的真实规则事件、首次上场去重、重复短版、操作优先、不暂停联机、减少动态、低画质及 2D 回退。没有新添等待进入规则链，也不因素材存在就标记 M1 已完成。
7. 其他卡的基础立绘仍按 AGENTS.md 的 2×2 / 3×2 批量图集流程制作；裁出每张稳定立绘后，再分别使用这套确定性的光效时间线。角色素材批量生产与单张角色的连续合成是两个阶段。

本目录包含 `.gdignore`，作为参考材料保存，复制到 Godot 项目时不应让整套参考图自动进入正式资源导入。
