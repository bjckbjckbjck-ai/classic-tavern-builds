# v0.50.0 发行验收

2026-09-17，Godot 4.6.1，Windows 3d 分支。十二张历史随从、两级机械马衍生物、四法术、多族适配、拱顶卡面与手绘桌面合并交付。当前内置池：207 定义，152 在池、29 退役、26 衍生物；41 法术、22 英雄、57 饰品。没有运行胜率或阵容平衡模拟。

## 验证范围

- 完整默认 headless 回归首次为 95/96 套、2287 条成功断言；唯一失败是旧 audit 测试遗漏饰品确认按钮。修正真实点击步骤并增加首次点选不付款检查后，该套 23 条通过。完整跑加定点复验合计覆盖 96/96 套、2291 条成功断言，不声称第二次完整绿跑。原始失败日志保留于 logs，详见 regression-triage.md 和 suites.json。
- 卡池生成器与实际 Godot Catalog 对照：Python 6/6，通过所有随从身份、普通/金色身材、七族成员、共享副本、法术及奖品文案、57 件饰品基础/转型报价及中立饰品空场资格。内置包顺序与游戏一致，不把用户 mods 混入发行清单。天灾之杖不再被中立种族门槛排除；已持有仍排除、不获转型折扣。
- 此前本版原生卡面回归 271 条及几何检查、23 张截图见 [卡面阶段证据](../issue18-card-surfaces/README.md)。本轮完整回归含新卡与新法术；未把同一条重复运行计为新增覆盖。
- 最终 EXE 两进程实测：原生 3D 客户端，通过实际买牌、出牌、买法术、施法、准备、非空战斗回放、私有快照及退出后 BOT 接管；双方 exit 0，最终日志无 ERROR。源码烟测曾出现退出资源清理告警，保留在 regression-triage.md。旧测试同帧连续发送过期 guard 已改为等待各次权威快照，正常请求和游戏规则不变。
- 最终 APK 在 Android API33 x86_64 模拟器覆盖安装，包名 org.classictavern.game、versionCode 53、versionName 0.50.0，沿用现有调试签名。设备 base.apk SHA-256 与发行 APK 完全相同；压缩包 CRC 正常，无 tests、references、.runtime 或签名私钥路径。ARM ABI 包含在包内，但未在实体 ARM 手机运行。
- 最终 APK 通过实际触控连接同机 QA 房主，检查四法术、流转实体 UID、亡语发现、四/十张微扇形手牌、首次点击不操作、长按详情、十手牌拖出正确实体、商店拖入宽容购买区、四选一饰品、天灾之杖先选后确认（20→17）、全部种族收藏及七族详情、法术分页、设置、2D/3D切换、公告、离开回到主菜单。随后从正常单机入口选择英雄、招募并进入战斗。记录见 android-actions.json、android-final/ 与日志。
- QA 房主固定八人局面和 1200 秒阅读计时，只存在于未导出的测试脚本。它验证真实客户端请求与 UI，不是自然完整对局，也不是外部两台实体设备的网络测试。
- 一次饰品自动点击指向空白的第二列，测试误报；按截图改点第一列后实际确认通过，原始误报和修正操作均保留。未修改游戏逻辑来通过该步骤。

## 明确限制

- 首次使用旧 SwiftShader 软件 GLES 的模拟器出现统一灰屏，日志是引擎 Scene/Canvas shader 的 GL_MAX_FRAGMENT_UNIFORM_VECTORS (261) 链接失败，与 [Godot 上游报告](https://github.com/godotengine/godot/issues/109550) 相同。切回上版已使用的宿主 GPU GLES 模式后，同一 APK 正常显示；仅调整本次模拟器启动参数，没有修改系统驱动、电源、代理或网络。没有修复或宣称支持该旧软件渲染器。
- 最终 APK 的宿主 GPU 模式没有 SCRIPT ERROR/ERROR，启动有 shader 缓存重编译警告。诊断截图的短期帧间隔仅为模拟器状态，不是手机性能或 GPU 耗时承诺。
- 未验证实体手机长局帧率、发热、音效实听；模拟器使用 no-audio。没有验证外网、异地两台设备、断网恢复或跨版本混联；本版协议要求两端均为 v0.50。
